# NetEdit Connection 视觉门设计

## 目标

为 TUM style 教师网和 Torii 候选网生成可重复的 NetEdit Connection 模式成对截图。视觉门应先用紧凑指标发现明显差异，只在失败或不确定时把图片交给模型检查。视觉门可以拒绝候选，但不能单独接受候选。

当前 Ingolstadt 样例必须成为首个真实回归样例。教师网在同一入口车道上显示黄色冲突关系，而当前 Torii 候选缺少这些关系。视觉门必须稳定识别该差异。

## 范围

视觉门检查一个目标 junction 及其机动车入口车道。它复用现有 NetEdit 启动、固定视窗、窗口截图、截图哈希和闭环记录能力。

本次不增加通用桌面控制层，不训练图像模型，不使用远程视觉服务，也不以整图像素相同作为通过条件。

## 输入

- TUM style 教师 `.net.xml`。
- Torii 候选 `.net.xml`。
- 教师 junction ID 与候选 junction ID。
- 教师和候选入口车道对应表。
- 固定窗口尺寸、缩放和目标区域边距。
- 输出目录。

每个输入文件都必须绑定 SHA-256。运行期间文件哈希变化时立即停止。

## 对齐

模块读取两张网的 `<location>`。它用 `netOffset` 把目标 junction 换算到共同的投影位置，再为两张网生成各自的 `viewsettings`。两次运行使用相同窗口尺寸、缩放、配色和目标区域大小。

入口车道点击点来自车道末端前的一段稳定位置。模块用固定视窗将该投影位置换算为窗口坐标。点击前后都保存截图和哈希。无法唯一确定窗口、入口车道或点击点时，结果为 `blocked`，不能改用猜测坐标。

## 运行流程

对每一对入口车道执行以下步骤：

1. 用 CLI 打开教师网，加载固定视窗。
2. 进入 Connection 模式并点击教师入口车道。
3. 保存完整截图和目标 junction 区域截图。
4. 关闭教师窗口。
5. 对候选网重复相同步骤。
6. 计算颜色层和局部形状指标。
7. 写入一条紧凑 JSON 记录。

运行器一次只保留一个 NetEdit 窗口，避免选错同名窗口。默认不把图片送入对话上下文。

## 视觉指标

模块只分析目标区域，并忽略菜单栏、侧栏、状态栏和光标附近的小区域。

标准配色层为：

- 青色：当前入口车道。
- 绿色：目标车道。
- 黄色：冲突关系。
- 紫色：通过关系。
- 深红色和灰色：junction 与道路轮廓。

每个颜色层记录像素数、连通块数和包围框。教师层在候选中完全缺失时直接失败。其余层允许少量抗锯齿误差和数像素平移。

道路轮廓先转成二值图，再在小范围平移内计算重叠率。该指标只发现大面积缺失、异常扩大和明显错位，不要求教师网与候选网逐像素相同。

## 判定

- `fail`：教师具有的关键颜色层在候选中缺失，连接层数量明显减少，或局部道路轮廓严重偏离。
- `review_required`：指标接近阈值、入口车道未稳定选中，或教师和候选采用不同但可能合理的 junction 分段。
- `pass`：所有入口车道的关键颜色层和局部轮廓均在允许范围内。
- `blocked`：NetEdit、窗口、文件哈希、视窗或点击点不可靠。

视觉 `pass` 不能自动接受候选。闭环只在以下条件同时成立时允许最终人工确认：

- 视觉门为 `pass`；
- Connection 结构检查为 `pass`；
- 表面检查为 `pass`；
- SUMO 载入为 `pass`；
- 真实行程检查完成且无新增异常；
- 候选与所有报告绑定同一 SHA-256。

## 输出

每次运行只产生必要文件：

- `visual-gate.json`：状态、哈希、输入、每条入口车道的指标和失败原因。
- `teacher-<lane>.png` 与 `candidate-<lane>.png`：原始目标区域截图。
- `comparison-<lane>.png`：失败或不确定时生成的并排图。
- 两个 `viewsettings` 文件，供复现。

成功时，调用者只需读取 `visual-gate.json`。失败或不确定时，调用者再查看并排图。这样可减少图片解码和对话 token。

## 接入闭环

在 `complete_tum_style_iteration` 接受候选前增加视觉门状态。`fail`、`review_required` 和 `blocked` 都不能写入 `accepted`。闭环的下一动作从失败入口车道和缺失颜色层生成，不再使用笼统的“检查截图”。

旧候选没有视觉记录时保持可读，但不能重新接受或宣称完成。

## 错误处理

- 文件或哈希不符：`blocked`。
- NetEdit 未找到或窗口不唯一：`blocked`。
- 截图尺寸、视窗或配色不符：`blocked`。
- 未识别到青色入口车道：`review_required`。
- 教师截图本身缺少预期颜色：`review_required`，避免用坏教师自动拒绝候选。
- 任何异常都写入 JSON；不得静默跳过入口车道。

## 检查策略

1. 纯图片检查：验证颜色容差、连通块、轻微平移和关键层缺失。
2. 假 NetEdit 会话：验证命令顺序、哈希绑定、失败关闭和紧凑输出。
3. 闭环检查：视觉状态不是 `pass` 时，`accepted` 必须失败。
4. 真实回归：当前 Ingolstadt 教师网与 Torii 候选必须得到 `fail`，原因包含黄色冲突关系缺失。
5. 修复后的候选必须在同一真实位置、同一入口车道和同一缩放下重新运行，旧截图不得复用。

## 明确不做

- 不使用全图感知相似度作为唯一标准。
- 不加入新的图像处理依赖；复用已安装的 Pillow。
- 不建立通用视觉工作流或插件协议。
- 不让视觉门修改路网。
- 不让视觉门单独提升候选状态。
