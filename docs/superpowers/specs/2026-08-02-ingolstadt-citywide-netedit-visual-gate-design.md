# Ingolstadt 全城 NetEdit Connection 视觉门设计

## 目标

从已经通过的 `cluster_2230504019_376231769` 开始，逐步扩大范围并真实运行 Torii。最终覆盖官方 TUM Ingolstadt 路网实际边界内的全部适用路口。每个适用路口都必须通过 Connection 视觉门、连接结构检查、SUMO 载入和全局可达性检查。

视觉门只负责提供可复现证据并拒绝不合格候选，不能单独接受候选。发现失败后，应修复 Torii 共用重建流程中的根因，再重建受影响分区及其相邻分区。默认用 NetEdit CLI；只有 CLI 无法表达的必要操作才使用 MCP。

## 权威范围与输入绑定

“全城”指官方 TUM-VT `sumo_ingolstadt` 当前网络的实际 `convBoundary`，不是行政边界，也不是 `<location>` 中可能过时的 `origBoundary` 元数据。

- 来源：`https://github.com/TUM-VT/sumo_ingolstadt`
- 文件：`simulation/ingolstadt_24h.net.xml.gz`
- 压缩文件 SHA-256：`101412168ec627baa3a56d38226d8a850fee702b90437fb29546d6aadf5a86e7`
- 解压 XML SHA-256：`bbfef2f8afb66f29486395189fa7136e3fa7cce2b192afcbd50a6f1d9239a806`
- `netOffset`：`-672401.23,-5399632.08`
- `convBoundary`：`1243.52,0.00,11284.52,10137.01`
- 实际范围：约 `10.041 km × 10.137 km`
- 当前清点：12,138 个非 internal junction、122,877 条 edge、185,052 条 connection、1,484 个 `tlLogic`

每次全城运行都记录来源 URL、上述哈希、SUMO/NetEdit 版本、Torii 提交、OSM 输入哈希和生成参数。任一输入在运行中变化时立即停止，旧证据不能复用。

## 严格完成条件

适用路口定义为：非 internal junction，至少有一条允许机动车通行的入口 lane，且至少有一条允许机动车通行的出口 lane。每条机动车入口 lane 都必须进入视觉门。

全城完成必须同时满足：

1. 教师网和候选网中的每个适用路口都进入清单。
2. 每个适用路口被唯一映射；教师独有、候选独有和映射不唯一的数量均为零。
3. 每条机动车入口 lane 都有成对 NetEdit Connection 证据，且状态为 `pass`。
4. 每个路口的连接结构、车道权限、转向、冲突和信号语义检查均为 `pass`。
5. 候选全网可由 SUMO 载入，且没有新增错误。
6. 跨分区、跨城区的分层 OD 行程检查全部完成；失败、无路径、碰撞和新增 teleport 均为零。
7. 清单、证据和最终候选绑定同一组来源哈希与候选 SHA-256。

任何缺失项只能是 `fail`、`review_required` 或 `blocked`，不能降级为通过。若官方教师网和当前 OSM 确有时间差异，应保留为明确失败并请求裁决，不能静默排除。

## 范围扩展

运行从已验证路口所在分区开始，按相邻分区向外扩展，直到覆盖整个 `convBoundary`。分区只用于恢复、重试和限制 NetEdit 视窗，不改变全城判定。

默认分区边长为 250 m。该值只在首次真实校准时调整，使分区及其边界缓冲区能稳定落入现有固定缩放的 NetEdit 画布。每个分区带一个 junction 尺度的缓冲区，边界路口由拥有其中心点的分区负责；相邻分区仍记录交叉检查，避免漏检。

每个分区独立记录：

- 输入和候选哈希；
- 教师、候选适用路口清单；
- 路口及入口 lane 映射；
- NetEdit 会话状态和最后完成项；
- 各门状态、失败原因和重试次数。

运行中断后只重做未完成项。Torii 修复导致候选 SHA 改变时，只使受影响分区及其相邻分区失效；全城清单仍重新核对，防止范围变化未被发现。

## 教师与候选映射

两张网先通过 `<location>` 和共同投影坐标注册。路口映射依次使用：

1. 投影位置和候选邻域；
2. 道路来源与走向；
3. 入口和出口方向集合；
4. lane 通行类别与数量；
5. 已验证相邻路口关系。

距离阈值由已验证路口集合校准并写入清单，不在运行中自动放宽。一个教师路口可以对应候选中的一个复合路口组，但必须有明确、可逆的成员表。入口 lane 映射还要核对来路、行驶方向和机动车权限。

无法唯一确定的映射进入 `review_required`。视觉相似不能覆盖映射失败。

## 高效视觉检查

复用现有 `NeteditTargetSession`、固定窗口、Connection 模式点击、Pillow 色层提取和哈希绑定。不开通用桌面控制层，不加入图像模型，也不增加依赖。

每个分区依次建立一对持久 NetEdit 会话。教师会话和候选会话保持相同窗口尺寸、缩放、配色和投影中心。运行器在分区内平移视窗，并对每条映射入口 lane 执行真实 Connection 模式点击。会话异常只使当前分区重启，不让整城任务从头开始。

每次点击检查以下视觉语义：

- 青色当前入口 lane；
- 绿色目标 lane；
- 黄色冲突关系；
- 紫色通过关系；
- junction 与道路轮廓。

通过项保存裁剪后的四层语义 mask、连通块、包围框、角向分布、颜色像素数量和截图来源哈希。角向分布以路口中心归一化，可容忍 OSM 几何的小幅差异，但能发现错误转向和缺失连接。原始通过截图只存在于分区临时目录；语义 mask 和其哈希写入成功后即可清理。失败、不确定和阻塞项保留教师、候选完整截图及并排图，供人工检查。

这种方式仍对每条入口 lane 执行真实 NetEdit 视觉检查，但日常复核只读取紧凑 JSON 和小型 mask。只有失败项进入对话视觉上下文，从而减少图片存储和 token。

## 结构门与修复闭环

视觉结果必须与 XML 结构结果一致。每条入口 lane 同时核对目标 lane、方向、许可、`via`、`linkIndex`、冲突/通过语义和所属信号。视觉 `pass` 但结构失败时，整体仍失败。

失败处理顺序为：

1. 确认教师、候选、映射、点击和截图哈希没有漂移。
2. 把同类失败按共享连接重建路径归组。
3. 在 Torii 最上游的共用重建函数中修复根因。
4. 为根因留下一个最小回归检查。
5. 重建失败分区和相邻分区。
6. 重跑视觉门、结构门和 SUMO 门。
7. 全城完成前再次核对全局清单和可达性。

不得为单一路口写专用补丁。NetEdit CLI 用于检查和可表达的路网修改；MCP 仅在 CLI 缺少该操作且能保留同等证据时启用。

## 全局运行检查

候选全网先执行 SUMO 无界面载入和日志检查。随后从空间分区与道路等级分层生成固定种子的 OD 对：

- 每个非空分区至少有一个区内行程；
- 每对相邻非空分区至少有一个跨界行程；
- 城区四边与中心之间均有长距离行程；
- 主要道路等级和信号控制走廊都有覆盖。

OD 端点只从允许机动车通行且连通的 lane 选择。报告记录生成规则、固定种子、route 数量、无路径、到达、teleport、碰撞和 SUMO 退出状态。教师网已知的人行连接限制和 WAUT 要求单独记录，不能用来放宽候选机动车完成条件。

## 产物

```text
outputs/.../ingolstadt-citywide-gate/
  city-manifest.json
  source-ledger.json
  tiles/<tile-id>/state.json
  tiles/<tile-id>/junctions/<pair-id>/lane-<id>.mask.png
  tiles/<tile-id>/failures/<pair-id>/teacher-<lane>.png
  tiles/<tile-id>/failures/<pair-id>/candidate-<lane>.png
  tiles/<tile-id>/failures/<pair-id>/comparison-<lane>.png
  global-load.json
  global-routeability.json
  completion.json
```

`city-manifest.json` 是覆盖分母和状态的唯一来源。`completion.json` 只汇总，不覆盖分区事实。任何报告都包含其直接输入和输出哈希。

## 最小实现边界

只扩展已有模块：

- `netedit_connection_visual_gate.py`：复用会话并输出紧凑 mask；
- `tum_style_closed_loop.py`：接收分区状态并保持严格接受条件；
- 一个全城运行脚本：清点、分区、恢复和汇总；
- 对应的最小检查。

不建立任务服务、资料库、通用图像框架或新的配置体系。第一版只保留真正需要校准的分区边长、边界缓冲和映射距离阈值。

## 停止条件

任务只在严格完成条件全部满足时结束。出现以下情况时暂停并保留可恢复状态：

- 官方来源或候选输入变化；
- 路口或 lane 映射不唯一；
- NetEdit 会话、Connection 点击或截图不能可靠复现；
- 同一根因连续三轮仍无法修复；
- 时间差异需要用户决定是否修改完成标准。
