# TUM Self-Replay Corpus Spec

## Target

Torii-SUMO should learn TUM-style junction cleanup in this order:

1. Replay selected TUM reference junctions from code and prove the replayed
   junction is identical to the TUM teacher under a canonical XML and NetEdit
   semantics comparison.
2. Convert repeated TUM replay observations into reusable, non-Ingolstadt
   junction rules and templates.
3. Apply those rules to OSM-derived Torii initial networks and verify whether
   the generated junction approaches the TUM reference.

This replaces the earlier default of starting directly from a Torii candidate
and trying to patch it toward TUM. The new first question is: can Torii
deterministically reproduce the teacher itself?

This spec covers the junction-local replay layer. Road-corridor connectivity
is a separate teacher layer because TUM-style edge chaining, road splitting,
boundary continuity, and non-junction connections can differ even when the
junction-internal movement graph is correct. Use
`docs/superpowers/specs/2026-07-01-tum-road-connectivity-replay.md` for that
parallel road layer, then integrate both gates before making full-network
claims.

## Control Loop

- target: code-replay TUM junctions so their junction, connection, TLS,
  walkingarea, crossing, internal edge, and internal junction semantics match
  the TUM teacher.
- current_state: Torii has teacher-guided candidate repair tools and pattern
  extraction, but the teacher modeling layer is mixed with candidate mapping
  and repair behavior.
- deviation: candidate failures can hide whether the root issue is teacher
  extraction, replay materialization, candidate approach mapping, or generic
  OSM inference.
- control_action: introduce a TUM self-replay gate before candidate repair.
- feedback: canonical XML parity, SUMO load, NetEdit semantic parity, local
  NetEdit screenshot review, and a corpus report grouped by reusable junction
  pattern.
- stopping_condition: at least one simple TUM three-way or four-way junction is
  code-replayed with zero canonical semantic delta and SUMO load success before
  any OSM-to-TUM reproduction claim is upgraded.

## Definitions

- TUM teacher: the human-cleaned SUMO reference network.
- Self-replay: a network written by Torii code from the TUM teacher model, not
  a hand-edited file and not a Torii OSM candidate.
- Canonical XML parity: equality after deterministic normalization of the
  relevant SUMO elements and attributes. Raw byte equality is useful only for
  exported review artifacts; it is not the scientific gate because SUMO/XML
  writers may reorder attributes.
- NetEdit semantic parity: equality of the tables NetEdit exposes visually:
  connections, linkIndex, phase states, requests, crossings, walkingareas,
  internal lanes, internal junctions, and junction attributes.
- Replay corpus: a set of selected TUM junctions with teacher model JSON,
  replayed net, parity report, SUMO load log, and visual review entry.
- Learned rule: a reusable pattern stated in topology, modal, movement, TLS,
  and internal-junction terms. A rule may not depend on Ingolstadt ids,
  coordinates, or exact TUM edge ids.

## Workflow

1. Select a small TUM junction for the replay corpus.
   - Prefer one three-way or four-way junction with clear arms.
   - Include at least one TLS case and one non-TLS case before promoting the
     corpus beyond prototype status.

2. Extract the complete teacher junction bundle.
   - Main junction attributes and requests.
   - Incident vehicle approach edges and lanes.
   - Vehicle connections, including `dir`, `state`, `via`, `tl`, `linkIndex`,
     `linkIndex2`, and lane indices.
   - TLS logic and all phases referenced by the junction.
   - Internal edges, lanes, connections, and internal junctions.
   - Crossings, walkingareas, and pedestrian/bicycle connections.
   - Boundary junctions needed for a loadable local replay net.

3. Materialize a self-replay net from the extracted bundle.
   - The output must be generated by code from the teacher bundle.
   - It may copy teacher element values, but it must pass through the same
     parser/writer path that later candidate replay will use.
   - It must not depend on a Torii OSM candidate.

4. Compare teacher versus self-replay.
   - Canonical XML tables must have zero delta.
   - The extracted teacher model from the replayed net must equal the original
     teacher model after deterministic normalization.
   - SUMO must load the replayed net.
   - NetEdit review artifacts must be generated for human screenshot review.

5. Record reusable lessons.
   - Group successful cases into three-way, four-way, TLS, non-TLS,
     pedestrian/crossing, bicycle/sidewalk, and turnaround-aware patterns.
   - Convert only repeated or clearly justified behavior into reusable code.
   - Keep single-case observations diagnostic unless the rule can be stated
     without Ingolstadt-specific ids or coordinates.

6. Return to OSM-to-TUM reproduction.
   - Generate Torii initial network from OSM bbox.
   - Classify the candidate junction topology.
   - Select a learned TUM-style pattern or rule.
   - Replay the rule onto the candidate.
   - Verify with SUMO load, routeability, parity gates, and NetEdit review.

## Exactness Gates

The self-replay phase passes only when these gates pass for the selected
junction:

- `sumo_load`: `sumo -n replay.net.xml` exits with code `0`.
- `junction_model_parity`: normalized teacher model equals normalized replay
  model.
- `connection_parity`: vehicle, pedestrian, internal, and walkingarea/crossing
  connections match after canonicalization.
- `tls_parity`: TLS id, type, program, phase order, phase state, and controlled
  link indices match.
- `internal_parity`: internal edges, lanes, internal junctions, shapes,
  requests, and internal connections match.
- `modal_parity`: crossing and walkingarea counts, shapes, widths, permissions,
  and crossing edge sets match.
- `visual_review_ready`: NetEdit-openable local teacher and replay nets exist,
  with a recorded command for opening them in connection mode.

## Non-Goals

- Do not claim arbitrary-city TUM-level generation without a teacher.
- Do not hardcode Ingolstadt ids, edge names, junction ids, or coordinates in
  reusable logic.
- Do not make TUM self-replay pass by byte-copying the original full net and
  calling it generation.
- Do not relax parity gates to make a corpus case pass.
- Do not use mismatch count reduction as the primary signal when approaches,
  crossings, walkingareas, or TLS are deleted.

## Claim Boundary

Passing one self-replay junction supports only:

```text
diagnostic-demo: Torii can code-replay one TUM teacher junction under explicit
canonical semantics gates.
```

Passing a multi-case TUM self-replay corpus supports:

```text
reference-teacher-replay: Torii can deterministically replay selected TUM
junction patterns and extract reusable TUM-style rules.
```

Only after OSM/Torii candidates pass the same gates may the workflow claim:

```text
reference-guided OSM-to-SUMO junction cleaning for covered TUM reference areas.
```
